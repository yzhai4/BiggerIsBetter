# 版本管理与验收规则

本仓库用于实际源码、差异、测试和回滚点，不用聊天中的版本号代替文件。

## 三类版本分开

`main` 保存项目索引与已审阅文件；`experiments/` 中的模块仍是实验，不因进入 main 就自动上线。`archive/world-impact-0.1.0` 保存本次导入的可恢复基线；这是普通 Git 分支，不是受保护或不可变标签，归档后不应继续提交。后续开发使用 `feature/*` 分支和 Pull Request。

线上静态文件恢复后，另建 `snapshots/sites-v15/` 或标明实际抓取日期的快照。只有核对到版本号才能叫 v15。抓取当前页面不能恢复 v1-v14 的历史源码，也不能恢复服务器逻辑或原 Git 历史。

## 每次发布记录

记录：版本号、来源提交、改动、测试范围、是否真机、部署地址、实际部署结果、已知问题、回滚提交。版本索引见 `versions/index.json`。

GitHub 归档和 Actions 构建不自动发布到原 Sites 站点。没有配置发布凭证或 Pages；不得虚构新的在线试玩地址。

## 本阶段冻结范围

只完成现有 M/A/N/F 的即时能力 → 道路与敌人变化 → 本轮后果 → 跨轮回响 → 死亡重开。保持全球陆地变异、农村轮椅起点、左向右地面道路、大小可读和胜利成长。真实力量与显示缩放分离。不新增路线、大型剧情树或正式图像/音频资产。

## 安全与完整性

不提交令牌、Cookie、个人存档或 .env。只归档授权的公开游戏代码；遇到认证、管理策略或网络限制时记录失败，不绕过。未知站点 HTML 不等于经过审阅的源码。CI 只读仓库、运行本地测试并生成候选包，不持有原站点部署权限。

## 后续集成门槛

确认原源码及旧存档结构后，检查爆发与能力按钮是否冲突、世界暂停、重复碰撞去重、F 复苏先后顺序、跨轮真实力量保留、死亡清空本局与保留局外成长，再用正式关卡完成真实 Boss 战验收。
