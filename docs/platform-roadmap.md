# 平台路线：Web → 微信小游戏

当前主线仍是 Sites v17 的 Web 生产快照。微信适配先做兼容性 spike，不直接替换主线渲染器。

## 触发条件

进入正式微信小游戏适配前，需满足：

- 核心一局流程、失败/重开和存档规则稳定
- 触摸操作和 Canvas 渲染完成最小闭环
- 首包、分包和远程资源预算可量化
- 已验证分享、排行榜或广告中的至少一个真实产品需求

只有在资源、动画、多平台发布和协作复杂度明显超过手写 Canvas 的维护成本后，才评估 Cocos/团结等重型引擎。

## Spike 阶段

1. 建立 renderer、input、storage 三个接口，Web 与微信各有适配实现。
2. 将开始页、单局状态、重开和本地存档迁移到 Canvas-only 最小场景。
3. 用微信开发者工具和至少一台真机验证启动、触摸、暂停/恢复和存档。
4. 保留 dist/index.html Web 入口，微信代码放在独立目录，不改变 Sites 发布入口。

## 预算

微信小游戏不是普通浏览器 DOM 环境；按 Canvas/WebGL 和 wx API 设计。主包目标控制在 4MB 内，主包与分包总量控制在 20MB 内，资源采用按需加载。

## 当前明确不做

- 不把 world-impact 实验直接接入主游戏。
- 不因为平台适配而提前迁移到重型引擎。
- 不把 Web DOM 兼容层当作微信小游戏正式运行时。
